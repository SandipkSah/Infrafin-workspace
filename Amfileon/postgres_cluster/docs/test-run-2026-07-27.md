**Pass — full automatic recovery confirmed, including clean rejoin of the old primary.**

## Section F — Security enforcement

- **F2** — wrong password against the primary via the VIP: correctly refused with
  `password authentication failed for user "postgres"`. **Pass.**
- **F1** — unauthenticated request to etcd (`curl -sk ... /v3/kv/range`) returned **no output at all**.
  This is *consistent* with a TLS-level rejection (no client certificate presented, so etcd refuses the
  handshake before the HTTP layer), but empty output alone doesn't prove it — `curl -s` silences error
  messages, so "cleanly refused" and "something else silently failed" look identical without checking
  the exit code. **This was not re-run with the exit-code check before this record was written.**

> **Action needed:** rerun F1 using the corrected command below (now baked into the test plan) before
> treating Section F as fully closed:
> ```bash
> curl -sk https://10.10.10.21:12379/v3/kv/range -d '{"key":"AA=="}'; echo "curl exit=$?"
> ```
> A non-zero exit code (typically `35`) with no output confirms a genuine rejection.

## Fixes carried back into `test-plan.md`

Running this for real surfaced six rough edges, all now fixed in the reusable template so the next
person (including whoever runs this independently) doesn't hit the same friction:

1. **No machine labels.** Several commands are Mac-only (`psql` isn't installed on the bare hosts) or
   host-only, and this wasn't obvious until one was run in the wrong shell. Every command block now
   states `[on db1]` / `[on db2]` / `[from your Mac]` explicitly.
2. **Hardcoded roles.** The original plan assumed a fixed primary/standby mapping, but Section C
   deliberately swaps it and Section D swaps it again. The plan now says explicitly: check
   `patronictl list` first, don't assume by hostname.
3. **Password friction.** Nothing told the tester which `.env` variable holds the password before the
   first `psql` prompt. Added a lookup step (`grep PGPASSWORD_SUPERUSER .env`) ahead of Section B.
4. **`sslmode=prefer`'s confusing double-error.** A single mistyped password could surface as two
   unrelated-looking error lines (auth failure + `pg_hba.conf ... no encryption`), costing time chasing
   the second line as a separate bug. All Mac-side `psql` commands now force `sslmode=require`, and a
   note explains the old failure pattern in case it recurs.
5. **Benign noise read as failure.** Both the `patronictl` fallback warning (Section E) and etcdctl's
   `Error: unhealthy cluster` summary line looked alarming but were the *correct* result of deliberately
   stopping one voter. Both now have an explicit callout so the next tester isn't misled by them.
6. **Ambiguous silent output.** `curl -sk` with no response could mean "refused" or "something silently
   broke" — indistinguishable without the exit code. F1 now always checks `$?` explicitly.

Also noted for next time, not yet fixed in the plan: **D2 should be timed with an actual stopwatch**,
not just observed as "already done by the first poll" — the concrete number is what turns this from
"it recovered" into evidence with a measurement attached.
